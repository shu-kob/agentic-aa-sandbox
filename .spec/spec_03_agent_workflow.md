# Phase 3: エージェント・ワークフローの結合テスト

## 概要
読者が簡単に検証できるように、Phase 1と2で作成したコンポーネントを組み合わせたシナリオテストを作成してください。

## 1. テストシナリオの実装
ファイル名: `test/AgentWorkflow.test.ts`
テストフレームワークとして Mocha / Chai を使用し、以下のシナリオをコードで表現してください。

### シナリオ: 「エージェントによる自動少額決済ワークフロー」
1. **初期設定 (Setup)**
   - ユーザー（Owner）、エージェント（Agent）、ポリシーエンジン（PolicyEngine）のアカウントを用意する。
   - `AgentRegistry` と `AgentSmartAccount` をデプロイする。
   - ユーザーのスマートアカウントに 1000 ETH（モック資金）を入金する。
2. **アイデンティティの確立 (EIP-8004)**
   - エージェントを `AgentRegistry` に登録し、Agent IDのNFTを取得する。
3. **権限の委譲 (Delegation)**
   - ユーザーがスマートアカウントを通じて、エージェントに対し「1回あたり最大 10 ETH まで」の制限付き実行権限（セッションキー）を付与する。
4. **インテントの生成 (TIS)**
   - エージェントが「5 ETH を別のアドレスに送金する」という TIS を生成し、署名する。
5. **ポリシー審査と承認 (PDR)**
   - ポリシーエンジン（オフチェーンスクリプト想定）が TIS を検証し、上限額（10 ETH）以内であることを確認して APPROVE の PDR（EIP-712署名）を発行する。
6. **オンチェーン実行とレピュテーション更新**
   - エージェントが TIS と PDR をスマートアカウントに送信し、トランザクションを実行する。
   - 実行成功後、`AgentRegistry` のレピュテーションスコアを加算する。
7. **失敗の検証 (ネガティブテスト)**
   - エージェントが上限を超える（例: 20 ETH）TISを生成した場合、ポリシーエンジンが REJECT を返す、あるいはコントラクトで Revert されることを確認する。

## 2. 確認手順
`npx hardhat test` を実行し、すべてのテストがパスすることを確認してください。コンソール出力には、ワークフローの各ステップ（例: "TIS Generated", "PDR Approved"）を分かりやすく `console.log` で出力するようにしてください。
